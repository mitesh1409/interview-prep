# What is PM2 and how does it help in managing Node.js applications in production?

PM2 — Node.js Process Manager

---

## Why PM2? — The Problem First

When you run a Node.js app in production with just `node server.js`:

```bash
node server.js
# ✅ App runs
# ❌ App crashes → stays down until someone manually restarts it
# ❌ Server reboots → app doesn't start automatically
# ❌ Uses only 1 CPU core — wastes remaining cores
# ❌ No logs management — console output lost
# ❌ No way to monitor memory/CPU usage
# ❌ Deploying new code = downtime
```

You'd have to solve all of this yourself. PM2 solves all of it out of the box.

---

## Without PM2 — What You'd Have to Build Yourself

| Problem | DIY Solution | Complexity |
|---|---|---|
| App crash recovery | Write a bash script to restart on crash | Error prone |
| Start on server reboot | Configure systemd/upstart service manually | Complex |
| Multi-core utilization | Write cluster code manually | Boilerplate |
| Log management | Redirect stdout to files, rotate manually | Tedious |
| Zero downtime deploys | Build your own rolling restart logic | Very complex |
| Process monitoring | Build a dashboard or use separate tools | Significant effort |

PM2 handles all of the above with simple commands.

---

## What PM2 Offers — Key Features

### 1. Auto Restart on Crash

```bash
pm2 start server.js --name "subscription-api"

# App crashes → PM2 automatically restarts it within seconds
# Configurable max restarts to avoid restart loops
```

### 2. Start on Server Reboot

```bash
pm2 startup   # generates and configures system startup script
pm2 save      # saves current process list

# Server reboots → PM2 starts automatically → your app starts automatically
```

### 3. Cluster Mode — Multi-Core Utilization

```bash
# -i max = one instance per CPU core — zero cluster code needed
pm2 start server.js -i max

# On a 16-core server:
# Spawns 16 instances automatically
# Load balances incoming requests across all 16
```

No need to write any `cluster` module code yourself.

### 4. Zero Downtime Deploys

```bash
pm2 reload subscription-api
# Restarts instances one by one — app stays available throughout
# Old instance keeps serving requests until new one is ready
```

vs

```bash
pm2 restart subscription-api
# Stops all → starts all — brief downtime
```

### 5. Log Management

```bash
pm2 logs                    # tail all logs in real time
pm2 logs subscription-api   # logs for specific app
pm2 flush                   # clear all log files
```

Logs are automatically written to `~/.pm2/logs/`:
```
subscription-api-out.log   ← stdout (console.log)
subscription-api-error.log ← stderr (console.error)
```

Install `pm2-logrotate` module to auto-rotate logs and prevent disk from filling up:
```bash
pm2 install pm2-logrotate
```

### 6. Process Monitoring

```bash
pm2 monit   # real time dashboard
pm2 list    # quick status of all processes
```

```
┌─────────────────────┬──┬──────┬───────┬────────┬─────┬──────────┐
│ Name                │id│ mode │ pid   │ status │ cpu │ memory   │
├─────────────────────┼──┼──────┼───────┼────────┼─────┼──────────┤
│ subscription-api    │0 │cluster│12345 │ online │ 2%  │ 85.2 MB  │
└─────────────────────┴──┴──────┴───────┴────────┴─────┴──────────┘
```

### 7. Ecosystem Config File — Environment Management

Instead of long CLI commands, define everything in a config file:

```javascript
// ecosystem.config.js — commit this to Git
export default {
  apps: [{
    name: 'subscription-api',
    script: './src/server.js',
    instances: 'max',          // cluster mode — one per CPU core
    exec_mode: 'cluster',
    watch: false,              // don't watch files in production
    max_memory_restart: '500M', // restart if memory exceeds 500MB

    env: {                     // development environment
      NODE_ENV: 'development',
      PORT: 3000,
    },

    env_production: {          // production environment
      NODE_ENV: 'production',
      PORT: 8080,
    },
  }],
};
```

```bash
pm2 start ecosystem.config.js --env production
```

---

## Common PM2 Commands Reference

```bash
pm2 start ecosystem.config.js --env production  # start app
pm2 stop subscription-api                        # stop app
pm2 restart subscription-api                     # restart (brief downtime)
pm2 reload subscription-api                      # zero downtime restart
pm2 delete subscription-api                      # remove from PM2

pm2 list                                         # show all processes
pm2 monit                                        # real time monitoring
pm2 logs                                         # tail logs

pm2 startup                                      # configure auto-start on reboot
pm2 save                                         # save current process list
```

## Is PM2 Widely Used?

Yes — PM2 is the **most widely used** Node.js process manager with over **50 million downloads per month** on npm. It is the de facto standard for managing Node.js apps on a VPS or dedicated server.

---

## Alternatives to PM2

| Tool | Type | Best For |
|---|---|---|
| **PM2** | Process manager | VPS/dedicated server — most popular |
| **systemd** | OS-level service manager | Linux servers — no extra install needed, lower level |
| **Docker + Docker Compose** | Containerization | Containerized deployments — handles restarts via restart policies |
| **Kubernetes** | Container orchestration | Large scale microservices — overkill for single apps |
| **Nodemon** | Dev only | Development only — never use in production |

---

## When to Use What

```
Single VPS / dedicated server
        └──▶ PM2 — easiest, most features, industry standard

Containerized deployment (Docker)
        └──▶ Docker restart policies replace PM2
             (Docker handles crash recovery and restarts)

Large scale microservices on cloud
        └──▶ Kubernetes — handles everything at infrastructure level
             (PM2 not needed inside containers)
```

In short — if you're deploying a Node.js app on a plain Linux server, **PM2 is the standard choice** and is what most teams reach for first.

## Is PM2 part of the application? Meaning once my project is ready to be deployed on production, do I need to install and configure PM2 as part of my project?

No - PM2 is **not part of your application**.  
It sits **outside** your application at the server/infrastructure level.

---

## The Mental Model

```
Server (Linux)
├── PM2 (installed globally on the server)        ← infrastructure level
│     └── Manages and runs your application
│
└── Your Node.js Application                      ← application level
      ├── src/
      ├── package.json
      ├── ecosystem.config.js  ← only this file is PM2-related
      └── node_modules/
```

PM2 is a tool that **lives on the server** and manages your app from outside — like how Nginx sits on a server and manages HTTP traffic without being part of your app.

---

## How It's Installed

```bash
# Installed GLOBALLY on the server — not inside your project
npm install -g pm2

# Verify
pm2 --version
```

Notice `--global` flag — it goes on the server, not in your project's `node_modules`. It won't appear in your `package.json` dependencies.

---

## What IS Part of Your Project

The only PM2-related file you commit to your repository is the **ecosystem config file**:

```
your-project/
├── ecosystem.config.js   ✅ commit this — PM2 config for your app
├── src/
├── package.json          ← PM2 is NOT listed here as a dependency
└── .gitignore
```

```javascript
// ecosystem.config.js — this lives in your project
export default {
  apps: [{
    name: 'subscription-api',
    script: './src/server.js',
    instances: 'max',
    exec_mode: 'cluster',
    max_memory_restart: '500M',
    env_production: {
      NODE_ENV: 'production',
      PORT: 8080,
    },
  }],
};
```

---

## The Deployment Flow

```
Developer machine                    Production Server
─────────────────                    ─────────────────
git push origin main    ──────────▶  git pull origin main
                                     npm install
                                     pm2 start ecosystem.config.js --env production
                                            ↑
                                     PM2 already installed on server globally
                                     your app is now running and managed by PM2
```

---

## Summary

| | Part of your app? | Where it lives |
|---|---|---|
| PM2 | ❌ No | Installed globally on the server |
| `ecosystem.config.js` | ✅ Yes | Your project repo — commit it |
| Your app code | ✅ Yes | Your project repo |

Think of PM2 the same way you think of Node.js itself — you don't bundle Node.js inside your project, you install it on the server. PM2 works the same way.
