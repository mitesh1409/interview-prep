# How to implement authentication like Netflix, Amazon Prime etc. OTT platforms where multiple user logins are allowed.

How to implement authentication like Netflix, Amazon Prime etc. OTT platforms where  
multiple user logins are allowed.  

It has a max limit of user logins, once max limit is reached it asks newly logged in user  
to logout of anyone account.

---

## Solution from my side

I'll implement Stateful Authentication.  

Because here server needs control over user's authentication state (one or multiple logins).  

I'll then create a following database table to store session data.  

```
user_sessions
    id (this is session id)
    user_id (maps to id in users table)
    ttl (time to live, lifetime)
    created_at (or logged in at)
    logged_in_device (not sure about its type, but may be we can save browser/device info as string)
```

We are allowing multiple user logins but we have max login limit.  
Let say we are allowing max 4 logins at a time.  

So to implement this we have to check number of active logins.  

Code snippet (psuedocode) is as follows:  

```
After validating login credentials.  

We can get number of active logins from the user_sessions table by the user id.
Active login means created_at + ttl > current time.

active_logins + 1 - because active_logins we get from the session_data and  
+1 for counting the current login request.

if (active_logins + 1) > max_login_limit:
    Deny login, ask user to logout of anyone active login account.

Otherwise allow to login by creating a new session.
```

## Schema — Improvements

Your schema is mostly right but missing a few important columns:

```sql
user_sessions
├── id              (session id — use UUID, not auto-increment integer)
├── user_id         (foreign key → users table)
├── ttl             (time to live in seconds)
├── created_at      (when session was created / logged in at)
├── expires_at      (created_at + ttl — store computed value for faster queries)
├── last_active_at  (for sliding expiry — update on every request)
├── device_info     (browser, OS, device type — store as JSON string)
├── ip_address      (useful for security — detect suspicious logins)
└── is_revoked      (boolean — for force logout without waiting for TTL to expire)
```

**Why `expires_at` instead of just `ttl`?**

```sql
-- ❌ Your approach — has to compute every time
WHERE created_at + (ttl || ' seconds')::interval > NOW()

-- ✅ Better — direct comparison, faster, indexable
WHERE expires_at > NOW() AND is_revoked = false
```

**Why `is_revoked`?**

TTL tells you when a session naturally expires. But what if a user logs out early, or you want to force-logout a session? You need a flag to immediately invalidate a session without waiting for TTL to expire.

```sql
-- Force logout a specific session immediately
UPDATE user_sessions SET is_revoked = true WHERE id = 'session_uuid';
```

## The Active Sessions Query

```sql
-- Get count of active sessions for a user
SELECT COUNT(*) as active_count
FROM user_sessions
WHERE user_id = ?
  AND expires_at > NOW()      -- not expired
  AND is_revoked = false;     -- not manually logged out
```

## One Race Condition to Be Aware Of

Your current approach has a subtle race condition:

```
User A and User B both hit the login endpoint at the same time
Both read active_count = 3 (limit is 4)
Both see 3 + 1 = 4 ≤ 4 → both allowed
Result: 5 active sessions — limit bypassed ❌
```

Fix with a database transaction and row lock:

```sql
BEGIN TRANSACTION;

-- Lock this user's rows so no concurrent check can read stale count
SELECT COUNT(*) FROM user_sessions
WHERE user_id = ? AND expires_at > NOW() AND is_revoked = false
FOR UPDATE;  -- ← row lock

-- If count < limit, create new session
INSERT INTO user_sessions (...) VALUES (...);

COMMIT;
```

This is rare in practice for a consumer app but worth knowing for an interview.

## Session Validation on Every Request

Once sessions are created, every protected API request needs to validate the session:

```
Request comes in with session_id cookie
        │
        ▼
Look up session in user_sessions table
        │
        ├── Not found → 401 Unauthorized
        ├── is_revoked = true → 401 Session terminated
        ├── expires_at < NOW() → 401 Session expired
        │
        └── Valid → attach user to req.user → continue
                    UPDATE last_active_at = NOW() (sliding expiry)
```

## Complete Improved Schema and Flow

```sql
-- Schema
CREATE TABLE user_sessions (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID NOT NULL REFERENCES users(id),
  expires_at    TIMESTAMP NOT NULL,
  last_active_at TIMESTAMP NOT NULL DEFAULT NOW(),
  device_info   JSONB,           -- { browser, os, device_type }
  ip_address    VARCHAR(45),     -- supports IPv6
  is_revoked    BOOLEAN DEFAULT false,
  created_at    TIMESTAMP DEFAULT NOW()
);

-- Index for fast lookups
CREATE INDEX idx_user_sessions_user_id ON user_sessions(user_id);
CREATE INDEX idx_user_sessions_expires ON user_sessions(expires_at);
```
