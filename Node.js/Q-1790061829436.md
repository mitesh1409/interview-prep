# How to import modules which don't support ESM? OR When to use `createRequire` (from `module` - built-in Node.js core module) in ESM?

## What `createRequire` Does

In ESM (`import/export`) the `require` function is not available by default. `createRequire` lets you create a `require` function manually so you can use it inside an ESM module.

```javascript
import { createRequire } from 'module';

const require = createRequire(import.meta.url);
//                                    ↑
//                    tells require where to resolve modules from
//                    (same directory as the current file)

// Now use require() just like in CommonJS
const somePackage = require('some-cjs-package');
```

---

## When Do You Actually Need This?

This is needed **less often than you'd think** — most popular packages support both ESM and CJS today. You need `createRequire` only in specific situations:

```javascript
// Situation 1 — package only ships CJS, no ESM export
const legacyPackage = require('old-package-cjs-only');

// Situation 2 — loading a JSON file (ESM doesn't support JSON imports by default)
const packageJson = require('./package.json');
// Note: Node.js v22+ supports: import data from './file.json' with { type: 'json' }
// but createRequire is still a common workaround for older versions

// Situation 3 — dynamically resolving a module path
const modulePath = require.resolve('some-package');
```

---

## The Better Alternative — Check First

Before reaching for `createRequire`, check if the package supports ESM:

```javascript
// ✅ Most packages today support direct ESM import — try this first
import somePackage from 'some-package';

// ⚠️ Only use createRequire if the above fails with:
// "ERR_REQUIRE_ESM" or "does not provide an export named"
import { createRequire } from 'module';
const require = createRequire(import.meta.url);
const somePackage = require('some-package');
```

## Summary

| | Detail |

| Is the code correct? | ✅ Yes |
| When to use it | Only when a package doesn't support ESM imports |
| Most common use case today | Loading JSON files or truly legacy CJS-only packages |
| Try first | Direct `import` — most modern packages support ESM |
